Recipe cheat sheet

Every knob in the working config (E11, Llama-3.2-1B compact), grouped by the job it does.

Rule of thumb: cost knobs change seconds and GB. Learning knobs change how well the model fits the inputs. Only information knobs can raise a ceiling that every model shares. AUC moves only when the model's ranking of games changes, and Platt never changes that ranking.

Cost: speed and memory
quantization.mode4bit, NF4, double quantStores the frozen base weights in 4 bits. Gradients flow through them into the LoRA adapters only (QLoRA).E3: barely affects speed. 8-bit is the slowest mode. A bf16 run of the 1B is untested.
gradient_checkpointingoffOn, it recomputes activations instead of storing them: less memory, more compute.Off is 25% faster and fits with 4-bit.
micro-batch × accumulation8 × 4How the effective batch is split across forward passes. The math is the same either way.E3.
bf16, adamw_torch_fusedonThe numeric format and a faster implementation of the same optimizer.n/a
Learning: how the weights move
lora.r16Rank of the low-rank update ΔW = B·A added to each targeted matrix. Higher rank means more trainable capacity.r=32 tied XGBoost too. Capacity isn't the limit.
lora.alpha32Scales the update by α/r. With this 1/r scaling, the best learning rate barely depends on rank.α=32 is also what LoRA Without Regret used.
lora.target_modulesq, k, v, oThe weight matrices that get adapters. Yours are attention only. The MLP matrices (gate/up/down) hold most of the parameters.Untested here. TM: attention-only underperforms LoRA that includes the MLP layers.
lora.dropout0.05Randomly zeroes adapter inputs during training, as regularization.n/a
learning_rate2e-4Step size. TM finds the best LoRA rate is about 10× the full fine-tuning rate.E9 (1e-4 / 4e-4) deprioritized.
schedule, warmupcosine, 5%The rate ramps up over the first 5% of steps, then decays along a cosine curve.n/a
epochs1 (727 steps)Passes over the training set.test_run2: the 2nd epoch bought nothing. Eval plateaus by about step 200–300.
effective batch32Games averaged per update. Each outcome is close to a coin flip, so larger batches average away noise.At 8, 78% of steps hit the clip.
max_grad_norm1.0Clips the gradient so no single update is too large.0.3 clipped most steps.

Scoring

  • p_home = P(+) / (P(+) + P(-)) at the first answer token.
  • Platt: a logistic fit on validation, cross-fitted. It fixes the home lean (raw picks are ~70% home against 55% actual). It's monotonic, so AUC stays put.
  • Win rule: a run wins if it beats E4's 0.6286 by at least 0.002 and the paired bootstrap 95% interval excludes zero.
  • Bars: always-home 0.688 · 5-shot base 0.659 · all fine-tunes and XGBoost about 0.628. Polymarket on test scores 0.579 / 70.0%.
