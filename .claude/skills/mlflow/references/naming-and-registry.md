# MLflow Naming & Registry Reference

When to read: managing the model registry, setting up naming conventions, or debugging URI issues.

## Three-level hierarchy

### 1. Experiments (top level)
- Group related runs together
- Use stable, descriptive names: `nba_bets_classification`, `nba_bets_predictions`
- Avoid timestamps or run-specific info in experiment names

### 2. Runs (middle level)
- Individual training/inference executions
- Format: `{config_name}-{YYYYMMDD}-{HHMMSS}-{conference_filter}`
- Generated by `generate_run_name()` in `src/ml/training/experiment.py`

### 3. Registered models (production level)
- Production-ready models with automatic versioning
- Pattern: `nba_classification_{model_type}_{conference_filter}`
- Versions auto-created when registering the same name
- Only register production candidates (not every experimental run)

## Model aliases

Use aliases for production/staging routing:

```python
from mlflow.tracking import MlflowClient

client = MlflowClient()
client.set_registered_model_alias(
    name="nba_classification_random_forest_same",
    alias="Production",
    version=best_version
)
```

Common aliases: `Production`, `Staging`, `Champion`

## Tags for organization

```python
tracker.set_tags({
    "task": "classification",
    "config_file": config_path.stem,
    "experiment_type": "training",
    "model_type": best_model_name,
    "status": "production"  # or "experimental"
})
```

## Workflow examples

### Experimental run (don't register)
```python
# Config: register_model: false
tracker.log_model(model, registered_model_name=None)
# Use URI: runs:/<run_id>/model
```

### Production candidate (register)
```python
# Config: register_model: true
tracker.log_model(model, registered_model_name="nba_classification_random_forest_same")
# Use URI: models:/nba_classification_random_forest_same/5
```

### Production deployment (alias)
```python
client.set_registered_model_alias(
    name="nba_classification_random_forest_same",
    alias="Production",
    version=5
)
# Use URI: models:/nba_classification_random_forest_same/Production
```

## Common pitfalls

- **URI format confusion**: `models:/name/stage` requires the model to be registered; `runs:/<id>/model` works for any logged model
- **Unnecessary registration**: Use `register_model: false` for experimental runs — registering every run clutters the registry with useless versions
- **Version message is normal**: "Creating a new version of this model..." means MLflow is auto-versioning, which is expected behavior

| Level | Purpose | Naming convention | Example |
|---|---|---|---|
| Experiment | Group related runs | Stable, descriptive | `nba_bets_classification` |
| Run | Individual execution | Config + timestamp + conference | `my_experiment-20241215-143022-same` |
| Registered Model | Production models | Stable name, versions auto-created | `nba_classification_random_forest_same` |
